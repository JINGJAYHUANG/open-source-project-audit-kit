# Threat model

## Assets

- decision integrity;
- private repository information;
- credentials and local paths;
- audit evidence and timestamps;
- recommendation provenance.

## Threats

- unsupported ratings generated by an LLM or analyst;
- popularity metrics presented as adoption proof;
- stale dynamic facts;
- multiple maintainer-controlled pages treated as independent evidence;
- private repository contents copied into a public report;
- license, critical security, or privileged-default risks averaged away;
- local collector output misrepresented as a security audit;
- spreadsheet formula injection in CSV exports;
- malicious repository text influencing an automated reviewer.

## Controls

- schema and semantic validation;
- evidence required for every observed rating and resolved gate;
- explicit independence groups;
- absolute observation dates;
- unknowns retained in the score denominator;
- hard recommendation caps;
- no-network collector;
- public secret/PII scan;
- HTML escaping and CSV formula neutralization;
- synthetic examples only.

## Residual risk

The toolkit validates the form and arithmetic of an audit. It cannot guarantee that cited evidence is truthful, complete, current, or interpreted correctly. Human review remains necessary for legal, security, and high-impact adoption decisions.
